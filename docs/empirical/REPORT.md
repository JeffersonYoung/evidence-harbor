# EvidenceHarbor 实证验证

日期：2026-10-04。该报告记录真实执行的案例和限制，不把可定位引用等同于语义正确，也不将小样本比较当作模型排行榜。

## 方法与执行范围

三个课题共获取 7 份真实公开资料（5 个 HTML、2 个 PDF），记录原始字节 SHA-256。保存的文件通过产品实际上传 API、处理流水线、版本化资料、检索和证据服务入库；原始网站地址作为声明的来源记录。这里属于“导入已保存字节”，不冒充产品的在线抓取成功。执行使用同一 FastAPI 领域路径的 TestClient 与独立 SQLite 数据目录；生产 PostgreSQL、pgvector、Temporal 的直接集成测试另见工程验证记录。

原始第三方全文、完整检索包和重复模型输出没有放入公开仓库。公开文件保留来源链接、哈希、方法和测量结果。

## 1. 金融新闻

问题：两次 FOMC 声明的已发生政策决定发生了什么变化？

- [2026-07-29 声明](https://www.federalreserve.gov/newsevents/pressreleases/monetary20260729a.htm)记录维持 3.50%—3.75% 的目标区间
- [2026-09-16 声明](https://www.federalreserve.gov/newsevents/pressreleases/monetary20260916a.htm)记录提高 25 个基点至 3.75%—4.00%
- 两份声明均指出通胀偏高；上述事实不能直接确定后续市场回报

两份资料均完成版本化入库、引用校验、报告提案和测试工作区内的操作员发布。未执行交易、回测收益预测或账户操作。

## 2. 量化交易相关研究

问题：PBO/CSCV 与 DSR 如何帮助审查回测，而不被误当成盈利保证？

实际导入 [PBO 作者版 PDF](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)与 [DSR 作者版 PDF](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)。前者讨论样本内策略选择与样本外相对表现的关系；后者校正多次试验选择与非正态收益导致的表现膨胀。研究结论保持在方法用途与限制的范围内。

两个 PDF 经文本解析和页码定位形成可检索证据，并完成提案和操作员测试发布。该案例没有验证某项具体策略、没有金融数据集回测，也不证明复杂 PDF 表格、扫描件或公式的解析质量。真实文本 PDF 解析使用 pypdf；Docling/OCR 是另一个需本地模型部署验收的路径。

## 3. LLM 研究与接管实验

课题：增加推理时计算是否总会提高正确率？固定资料包括 [compute-optimal scaling](https://arxiv.org/html/2408.03314v1)、[s1](https://arxiv.org/html/2501.19393v3)和[复杂度研究](https://arxiv.org/html/2506.06941v1)。这三项研究说明了条件化收益、方法差异和适用范围，不能由此推导所有现行模型的普遍排名。

通过产品检索和证据服务生成固定的 15 块资料包，由独立研究 agent 接管同一个问题，输出六条有引用的结论和报告提案，再调用产品的证据验证与提案接口。比较矩阵为两个模型、low/high 两档推理强度、每格两次独立运行，共 8 次。各次使用相同任务与同一资料包，不进行额外联网检索。

模型名称是运行环境提供并在启动时请求的标识，不保证可直接作为公开模型 API 参数。实验没有使用用户的外部模型 API 密钥，也没有获得计费 token 或费用数据。模型服务后端的不可见路由与随机性没有被控制。

| 请求模型标识 | 请求推理强度 | 次数 | 盲评平均分 / 12 | 观察到的平均墙钟时间 | agent 最终提交成功 |
|---|---|---:|---:|---:|---:|
| gpt-6-luna | low | 2 | 10.5 | 91 秒 | 2/2 |
| gpt-6-luna | high | 2 | 12 | 125 秒 | 2/2 |
| gpt-6.1-sol | low | 2 | 12 | 99.5 秒 | 2/2 |
| gpt-6.1-sol | high | 2 | 12 | 127.5 秒 | 1/2 |

盲评由一个未见配置标签的 gpt-6-astra/high 评审执行，不是人工金标准。六个维度分别为机制准确性、范围限制、数值准确性、引用支持、分歧解释、证据缺口，各 0–2 分。两个扣分点涉及一个数值措辞含混，以及未充分区别“增加题目复杂度”与“固定题目增加计算”的实验含义。

48 条结论共 115 次引用 ID 引用，均来自经过验证的固定证据包。ID 有效不证明每个命题都得到充分支持，所以上表单独报告语义评审。

### 真实暴露的接口问题

原始实验任务没有说明服务要求每条 claim 文本逐字出现在 report content 中，8 次首次提交均被 422 拒绝。7 次运行根据错误修正格式并提交成功，1 次按停止条件结束。之后操作员只做确定性的格式规范化，保留原始输出，补交第 8 份成功。该补交不计为原 agent 成功。

这更明确地说明接口契约和错误恢复会影响接管效果，而不是证明某个模型较差。产品安装技能和模型提示应清楚说明该约束。开发期间后端仍有修复，固定的是资料和任务；最终版本的重验应与原始模型运行分开报告。

### 如何理解这些数字

此案例中，luna 的 high 两次得到更高盲评分，但耗时也更长；sol 两档的语义评分均达到本次量表上限。每格仅两次、一个问题、选定的三篇论文和单一评审，无法支持统计显著性、稳定的成本收益判断或普遍优劣结论。时间包含工具调用、格式修复和服务等待，不是纯模型推理延迟；费用和 token 均记为未知。

## 领域不变量检查

在真实导入的资料和测试报告上确认：

- 不存在于原块的引文被 422 拒绝
- 第一个基线版本 1 的报告修订发布为版本 2
- 使用旧基线的竞争修订被 409 拒绝，不静默覆盖
- 版本 1 与版本 2 均保留
- 对同一个采集版本采用不同分块配置生成新的处理版本
- 旧证据在重新处理后仍能读取，引用哈希保持一致

这些是应用行为验证，不等于生产灾难恢复演练。早期实证还发现导入来源元数据不应触发 DNS，以及已有测试数据库需要显式迁移；均经修复后重跑，失败经历没有被隐藏为一次成功。

## 复现与待集成

1. 按 README 安装依赖并初始化独立测试数据目录
2. 使用 sources.json 中的 URL 重新获取资料，记录实际字节和哈希；若网站内容变化，不应假装获得了完全相同的历史版本
3. 使用 scripts/empirical_harness.py ingest-manifest 导入已保存文件；原件放在仓库外
4. 通过 packet 子命令检索、注册并验证证据；按固定任务逐次调用所选 agent，保存模型配置和实际输出
5. 对输出进行机械验证，再对隐藏模型标签的案例做独立语义评审
6. 不把没有执行的外部 API、OCR 模型、S3 服务、Docker 网络隔离或客户端安装写成通过

本次真实原件及本地 ID 位于私有运行数据中，公开报告只保留相应内容哈希与测量记录。重新导入会生成新的对象 ID；任务必须引用实际生成的证据，不能照抄本次 ID。
